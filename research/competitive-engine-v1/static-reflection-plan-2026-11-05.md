# Static evaluation cache: audit left–right reflection reuse

On the shared quiet capture-bank rules, reflecting files preserves the ranks, move geometry, center-file bonuses, material, bank contents, check, and the number of legal actions. Static evaluation uses those quantities. The real static cache still keys the two boards separately. Score bounds, terminal adjudication, repetitions, and move hints are outside this question.

Measure exact misses on which the file-reflected key is already present in the real static cache. Reflect only the board component (reverse the four two-character occupant tokens within each rank); leave phase, turn, banks, rules, and rights byte-for-byte unchanged. Confirm equal computed scores on every such hit, excluding self-reflections. This is instrumentation only: calculate the normal value and preserve real keys, lookup order, capacity, and eviction. No cache entry is reused or inserted by the audit. Any mismatch stops the family.

Use only the 32 existing shared quiet capture-bank snapshots at indices 0, 4, …, 124 in js-legal-recaptures.json. No substitutions. Run each position once with and once without instrumentation, depth 4 iterative, max 100,000 nodes/200 ms per query, competitive q4 with checks/evasion2, LMR off, evaluation cache on, Q cache off, optional flags off and no RNG. Compare action, score, PV, depth and node count on jointly completed queries; require at least 28 jointly complete, and legal PV and restored input on every query. Retain capped results, total genuine misses and potential reflected hits per root, and the first 12 opportunities in traversal order. Time with instrumentation is not a speed measurement.

Stop unless reflected hits are at least 5% of genuine misses overall and occur in at least 8 distinct roots, with all correctness gates met. Even a pass only justifies a separate cost and correctness prototype. No rule/hash changes, other symmetries, candidate, opponent query, match, or production change in this diagnostic. Archive only the invoked engine modules, script, plan, inputs, outputs and logs.
