# Basecoat migration audit — 2026-09-13

## Ownership and scope

Five HTML documents share the locally bundled Basecoat 1.0.2 Nova stylesheet.
`ui.css` is the shared control/surface integration; `styles.css` continues to own
responsive page layout, board geometry, piece glyphs, drag ghosts, check states,
the advantage rail, and game motion. No new framework or production build step.

| Page | Controls and surfaces migrated | Preserved behavior |
| --- | --- | --- |
| Homepage | Header/theme/language/install buttons, mode cards, tutorial controls, rules dialog controls, online invitation clock form | First-visit lessons, offline availability, UUID invitations, native dialogs |
| Bot Arena | Seat selectors, training controls, playback buttons, transcript buttons, panel surfaces, editor action buttons and turn selector | AI workers, takeover/branching, editor piece palette, history scroll containment |
| Match | Header/actions, invitation fields/cards, reconnect/expired actions, result cards, training panel, playback actions, chat/media/quick messages, sound/rules/shortcut dialog controls | P2P, clocks, source-hidden drag, optional mic/camera, result focus and match state |
| Library | Filters, statistics surface, dynamically generated game cards, pagination, replay controls/transcript, provenance disclosure surface | Filtering, complete replay position/reserves, optional evaluation, play-from-here |
| Puzzles | Mix disclosures, checkbox labels, Next/Solution actions, shared controls | Random selected depths, hidden depth, auto-next, sticky mobile actions, solution feedback, drag/drop |

Board cells, reserve buttons and editor piece glyphs deliberately do not receive
Basecoat button classes: default button padding/disabled opacity would crop pieces,
change equal-square geometry, or reintroduce transparent reserves.

## Findings and integration decisions

- Buttons were independently restyled in each mode; one `.btn` vocabulary now
  supplies size, radius, focus, disabled state and primary/outline/ghost treatment.
- Language controls and library cards are generated by JavaScript, so changing
  static markup alone misses them. Their creators now use the same vocabulary.
- Native `<select>` and `<dialog>` preserve browser behavior and existing event
  bindings. Do not adopt Basecoat's custom widget runtime merely for visual parity.
- Schness's `data-theme` and palette remain authoritative. Basecoat semantic tokens
  are mapped to them; adding `.dark` would overwrite shared `--muted`/`--accent`
  defaults and is unnecessary here.
- Mobile targets remain at least 44px high. Japanese labels wrap horizontally,
  rather than clipping into narrow columns. Large mode cards are reduced to a
  quieter two-line hierarchy.
- Vendor CSS is a pinned, unmodified npm distribution with its MIT license. It is
  cached by the service worker and served from the same origin under existing CSP.
- The standalone bundle costs about 223KB uncompressed. A later selective build
  could reduce this, but would introduce maintenance/build tooling; measure the
  actual compressed transfer before choosing that tradeoff.

## Validation and rollback

Unit/source tests cover the shared CSS order, all five migrated documents, local
vendor/cache inclusion, preserved board ownership, and dynamic control styling.
Browser stories cover existing happy paths plus theme/language overflow and
visible control sizing on desktop and mobile. Native relay/microphone/camera use
still requires real devices and peers; styling tests are not evidence of networking.

The PR is squash-merged as one migration commit. Revert that commit to return to
the previous UI without changing saved games, tournament files, rules, or AI.
